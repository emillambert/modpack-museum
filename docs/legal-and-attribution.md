# Legal and Attribution Policy

This document is project policy, not legal advice.

## Core rule

A historical Minecraft mod being old, abandoned, difficult to download, or included in an old pack does **not** make its source code, textures, sounds, models, names, or logos public domain.

## Classification

Before reusing third-party material, classify it:

- **Permissive:** reuse according to its license and attribution requirements.
- **Copyleft:** reuse only while satisfying the license obligations.
- **Custom/restricted:** obtain permission if reuse is desired.
- **Unclear/closed:** do not copy code or assets; implement behavior cleanly from public documentation/observation and create new assets.

## Behavioral recreation

For closed/unclear projects, Modpack Museum should use new source code and project-owned art. Public documentation, old videos, wikis, manuals, and gameplay observation may be used as behavioral references. Do not submit decompiled proprietary implementation code.

## Branding

`Modpack Museum`, `Classic Tech`, `Classic Adventure`, `Classic Warfare`, and `The Archive` are project-facing names intended to avoid implying official status.

Tekkit, Hexxit, Voltz, Technic and historical mod/project names should be used descriptively and with clear attribution, not as if this project owns or officially continues them.

## Per-feature evidence

Significant fidelity features should eventually record:

- historical project/mod
- version/era
- behavior reference
- implementation status
- asset provenance
- license/permission status
- known intentional differences

A structured attribution registry should be created before any public release containing third-party assets.
